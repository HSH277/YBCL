# 登录验证原理说明 (JWT Token 机制)

## 一、整体架构

本项目采用 **JWT (JSON Web Token)** 实现无状态的用户身份验证，前后端分离架构下
的认证流程如下：

```
┌──────────┐        ┌──────────┐        ┌──────────┐
│  前端     │        │  后端     │        │  数据库   │
│ (浏览器)  │        │ (Express) │        │ (MySQL)  │
└────┬─────┘        └────┬─────┘        └────┬─────┘
     │                   │                   │
     │  1. POST /login   │                   │
     │  {username, pwd}  │                   │
     │──────────────────>│                   │
     │                   │  2. 查询用户       │
     │                   │──────────────────>│
     │                   │  3. 返回用户数据    │
     │                   │<──────────────────│
     │                   │                   │
     │                   │  4. bcrypt 比对密码 │
     │                   │  5. 生成 JWT Token │
     │                   │                   │
     │  6. 返回 token    │                   │
     │<──────────────────│                   │
     │                   │                   │
     │  7. 存入 localStorage                │
     │                   │                   │
     │  8. GET /cart     │                   │
     │  Header: Bearer <token>               │
     │──────────────────>│                   │
     │                   │  9. 验证 token     │
     │                   │  10. 解析用户ID    │
     │                   │  11. 查询数据      │
     │                   │──────────────────>│
     │  12. 返回数据      │                   │
     │<──────────────────│                   │
```

## 二、JWT Token 结构

JWT 由三部分组成，用 `.` 分隔：

```
eyJhbGciOiJIUzI1NiJ9.eyJpZCI6MSwidXNlcm5hbWUiOiJ0ZXN0In0.xxxxx
│       Header (头部)    │        Payload (载荷)          │  Signature (签名)  │
```

### 2.1 Header（头部）
```json
{
  "alg": "HS256",   // 签名算法: HMAC-SHA256
  "typ": "JWT"      // Token 类型
}
```

### 2.2 Payload（载荷）
```json
{
  "id": 1,                          // 用户ID
  "username": "testuser",           // 用户名
  "iat": 1717000000,                // 签发时间 (issued at)
  "exp": 1717604800                 // 过期时间 (expiration) = iat + 7天
}
```

### 2.3 Signature（签名）
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  JWT_SECRET    // 服务端密钥，不对外暴露
)
```

**签名的作用**: 防止 Payload 被篡改。任何人修改了 Header 或 Payload，
都无法生成正确的签名（因为没有密钥）。

## 三、后端实现细节

### 3.1 登录时生成 Token (`routes/auth.js`)

```javascript
// 用户密码验证通过后，生成 Token
const token = jwt.sign(
  { id: user.id, username: user.username },  // Payload: 用户身份信息
  JWT_SECRET,                                 // 密钥: 仅服务端持有
  { expiresIn: '7d' }                         // 有效期: 7天
);
```

### 3.2 验证 Token 的中间件 (`middleware/auth.js`)

每次请求受保护的接口时，中间件自动执行：

```javascript
function authMiddleware(req, res, next) {
  // 1. 从请求头提取 token
  const header = req.headers.authorization;  // "Bearer eyJhbG..."
  const token = header.split(' ')[1];

  // 2. 验证签名 + 有效期
  const decoded = jwt.verify(token, JWT_SECRET);

  // 3. 将用户信息挂载到 req 对象
  req.user = decoded;  // { id: 1, username: "testuser" }

  // 4. 放行到下一个路由处理函数
  next();
}
```

**验证失败的两种情况**:
- `TokenExpiredError`: Token 已过期 (超过 7 天)
- `JsonWebTokenError`: Token 签名无效 (被篡改或格式错误)

### 3.3 受保护的路由

```javascript
// 购物车和订单路由都需要经过 authMiddleware
router.use(authMiddleware);  // 该文件下所有路由都需要登录

// 路由处理函数中可通过 req.user 获取当前用户
router.get('/', async (req, res) => {
  const userId = req.user.id;  // 从 token 中解析出的用户ID
  // ... 查询该用户的订单
});
```

## 四、前端实现细节

### 4.1 登录成功后存储 Token (`login.html`)

```javascript
const res = await api.login({ username, password });
if (res.code === 200) {
  localStorage.setItem('token', res.data.token);      // 存储 token
  localStorage.setItem('user', JSON.stringify(res.data.user)); // 存储用户信息
  window.location.href = 'index.html';                 // 跳转首页
}
```

### 4.2 请求时携带 Token (`js/api.js`)

```javascript
async function request(url, options = {}) {
  const token = localStorage.getItem('token');
  const headers = { 'Content-Type': 'application/json' };

  if (token) {
    headers['Authorization'] = `Bearer ${token}`;  // 每次请求自动带上
  }

  const res = await fetch(BASE_URL + url, { headers, ...options });

  // 401 响应处理: token 过期或无效
  if (res.status === 401) {
    localStorage.removeItem('token');   // 清除无效 token
    window.location.href = 'login.html'; // 跳转登录页
  }

  return res.json();
}
```

### 4.3 前端 Token 过期预检

```javascript
// 解析 JWT Payload 检查是否过期 (无需请求后端)
function isTokenExpired(token) {
  const payload = JSON.parse(atob(token.split('.')[1]));
  return payload.exp * 1000 < Date.now();
}
```

### 4.4 登录守卫 (`js/auth.js`)

需要登录才能访问的页面 (如购物车、订单)，在页面加载时验证：

```javascript
async function requireAuth() {
  const res = await api.verifyToken();  // 调用后端验证接口
  if (res.code !== 200) {
    alert('请先登录');
    window.location.href = 'login.html';
    return false;
  }
  return true;
}
```

## 五、安全性说明

| 安全措施 | 说明 |
|---------|------|
| 密码加密 | 使用 bcrypt 算法，salt rounds = 10，数据库不存储明文密码 |
| Token 签名 | HMAC-SHA256 算法，密钥仅服务端持有，防篡改 |
| Token 有效期 | 7 天自动过期，减少泄露风险 |
| 统一错误提示 | 登录失败统一返回"用户名或密码错误"，不暴露具体原因 |
| SQL 参数化查询 | 所有数据库操作使用 `?` 占位符，防止 SQL 注入 |

## 六、数据流总结

```
用户输入用户名密码
       ↓
前端 POST /api/auth/login
       ↓
后端查询数据库 → bcrypt 比对密码
       ↓
密码正确 → jwt.sign() 生成 Token
       ↓
前端收到 Token → 存入 localStorage
       ↓
后续每次请求 → Header 携带 Bearer Token
       ↓
后端中间件 jwt.verify() → 验证通过 → 放行
                       → 验证失败 → 返回 401
       ↓
前端收到 401 → 清除 Token → 跳转登录页
```
