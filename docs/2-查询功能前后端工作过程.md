# 查询功能的前后端工作过程说明

本文档以**商品搜索**和**订单列表查询**两个典型场景，详细说明前后端数据交互的完整过程。

---

## 一、商品搜索查询

### 1.1 场景描述

用户在首页搜索框输入关键词"耳机"，同时选择"电子产品"分类，
前端实时向后端请求匹配的商品列表并渲染到页面。

### 1.2 完整数据流

```
┌─────────────────────────────────────────────────────────────────┐
│  前端 (浏览器)                                                    │
│                                                                  │
│  用户操作: 输入"耳机" → 选择分类"电子产品"                          │
│       ↓                                                          │
│  products.js: 搜索输入触发 input 事件                              │
│       ↓                                                          │
│  防抖处理: 等待 300ms 无新输入后触发请求                            │
│       ↓                                                          │
│  api.js: 构建请求                                                │
│    URL: GET http://localhost:3000/api/products?keyword=耳机&category=电子产品 │
│    Header: { Content-Type: application/json }                    │
│       ↓                                                          │
│  fetch() 发送 HTTP GET 请求                                      │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    HTTP GET /api/products
                    ?keyword=耳机
                    &category=电子产品
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  后端 (Express)                                                  │
│                                                                  │
│  routes/products.js → router.get('/')                            │
│       ↓                                                          │
│  1. 解析查询参数                                                  │
│     keyword = "耳机", category = "电子产品"                       │
│       ↓                                                          │
│  2. 动态构建 SQL                                                  │
│     let sql = 'SELECT * FROM products WHERE 1=1'                │
│     sql += ' AND name LIKE ?'     → params: ['%耳机%']          │
│     sql += ' AND category = ?'    → params: ['电子产品']         │
│     sql += ' ORDER BY created_at DESC'                          │
│       ↓                                                          │
│  3. 执行参数化查询 (防 SQL 注入)                                   │
│     pool.query(sql, params)                                      │
│       ↓                                                          │
│  4. MySQL 执行:                                                  │
│     SELECT * FROM products                                       │
│     WHERE 1=1 AND name LIKE '%耳机%' AND category = '电子产品'   │
│     ORDER BY created_at DESC                                     │
│       ↓                                                          │
│  5. 处理结果: 添加 lowStock 标记                                  │
│     products = rows.map(p => ({ ...p, lowStock: p.stock < 10 }))│
│       ↓                                                          │
│  6. 返回 JSON 响应                                               │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    HTTP 200 OK
                    Content-Type: application/json
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  前端 (浏览器) - 渲染阶段                                         │
│                                                                  │
│  products.js: 收到响应                                            │
│       ↓                                                          │
│  检查 res.code === 200                                           │
│       ↓                                                          │
│  遍历 res.data 数组，拼接 HTML                                    │
│  每个商品生成一个 .product-card 卡片:                              │
│    - 商品名称首字作为图标                                          │
│    - 显示价格 (红色)                                              │
│    - 显示分类                                                    │
│    - 库存 < 10 显示"库存紧张"标签，否则显示库存数                   │
│       ↓                                                          │
│  grid.innerHTML = html  → DOM 更新，页面显示商品列表              │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 关键代码对应

| 步骤 | 文件 | 代码位置 |
|------|------|---------|
| 用户输入触发 | `js/products.js` | `initSearch()` 中的 `addEventListener('input', ...)` |
| 防抖处理 | `js/products.js` | `setTimeout(() => { ... }, 300)` |
| 构建请求参数 | `js/products.js` | `loadProducts()` 中的 `const params = {}` |
| 发送 HTTP 请求 | `js/api.js` | `request(url, options)` 中的 `fetch(BASE_URL + url, config)` |
| 解析查询参数 | `routes/products.js` | `const { keyword, category } = req.query` |
| 动态 SQL 构建 | `routes/products.js` | `let sql = 'SELECT * FROM products WHERE 1=1'` + 条件拼接 |
| 参数化查询 | `routes/products.js` | `pool.query(sql, params)` |
| 结果处理 | `routes/products.js` | `rows.map(p => ({ ...p, lowStock: p.stock < 10 }))` |
| 返回响应 | `routes/products.js` | `res.json({ code: 200, data: products })` |
| 前端渲染 | `js/products.js` | `grid.innerHTML = res.data.map(...)` |

## 二、订单列表查询

### 2.1 场景描述

用户进入"我的订单"页面，默认加载全部订单；点击"待付款"筛选按钮，
只显示待付款状态的订单；点击"下一页"加载更多。

### 2.2 完整数据流

```
┌─────────────────────────────────────────────────────────────────┐
│  前端 (浏览器)                                                    │
│                                                                  │
│  orders.html 页面加载                                             │
│       ↓                                                          │
│  orders.js: DOMContentLoaded 事件                                │
│       ↓                                                          │
│  并行发起两个请求:                                                 │
│    1. api.getOrderStats() → GET /api/orders/stats                │
│    2. api.getOrders({ page: 1, limit: 10 })                     │
│       → GET /api/orders?page=1&limit=10                         │
│                                                                  │
│  api.js: 自动从 localStorage 读取 token                          │
│    Header: {                                                     │
│      Content-Type: application/json,                             │
│      Authorization: Bearer eyJhbG...   ← JWT Token              │
│    }                                                             │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    HTTP GET /api/orders
                    ?page=1&limit=10
                    Authorization: Bearer <token>
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  后端 (Express)                                                  │
│                                                                  │
│  第一层: authMiddleware (middleware/auth.js)                      │
│       ↓                                                          │
│  1. 提取 Authorization 头 → 获取 token                           │
│  2. jwt.verify(token, JWT_SECRET) → 解码出 { id, username }      │
│  3. req.user = decoded → 挂载用户信息                             │
│  4. next() → 放行到路由处理                                       │
│       ↓                                                          │
│  第二层: router.get('/') (routes/orders.js)                      │
│       ↓                                                          │
│  1. 解析分页参数                                                  │
│     page = 1, limit = 10, offset = 0                            │
│       ↓                                                          │
│  2. 查询总数 (用于分页计算)                                       │
│     SELECT COUNT(*) AS total FROM orders                         │
│     WHERE user_id = ?                                            │
│     → total = 25                                                 │
│       ↓                                                          │
│  3. 查询当前页数据                                                │
│     SELECT * FROM orders                                         │
│     WHERE user_id = ?                                            │
│     ORDER BY created_at DESC                                     │
│     LIMIT 10 OFFSET 0                                            │
│       ↓                                                          │
│  4. 返回分页结构                                                  │
│     {                                                            │
│       list: [...],        // 当前页 10 条订单                     │
│       pagination: {                                               │
│         page: 1,          // 当前页码                             │
│         limit: 10,        // 每页条数                             │
│         total: 25,        // 总记录数                             │
│         totalPages: 3     // 总页数                               │
│       }                                                          │
│     }                                                            │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    HTTP 200 OK
                    { code: 200, data: { list, pagination } }
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  前端 (浏览器) - 渲染阶段                                         │
│                                                                  │
│  orders.js: 收到响应                                              │
│       ↓                                                          │
│  渲染订单卡片:                                                    │
│    每条订单显示: 订单号、下单时间、状态标签、总额                    │
│    状态标签颜色: pending=黄 paid=蓝 shipped=紫 completed=绿       │
│       ↓                                                          │
│  渲染分页控件:                                                    │
│    [上一页]  第 1/3 页 (共 25 条)  [下一页]                       │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 状态筛选交互

```
用户点击"待付款"按钮
       ↓
filterByStatus('pending')
       ↓
设置 currentStatus = 'pending', currentPage = 1
       ↓
更新按钮样式: "待付款"高亮，其他恢复默认
       ↓
loadOrders() → api.getOrders({ status: 'pending', page: 1, limit: 10 })
       ↓
后端 SQL 增加条件: AND o.status = 'pending'
       ↓
只返回待付款状态的订单
       ↓
前端重新渲染列表和分页
```

### 2.4 订单详情交互

```
用户点击某条订单的"查看详情"按钮
       ↓
viewDetail(orderId) → api.getOrder(orderId)
       ↓
GET /api/orders/:id
  Header: Authorization: Bearer <token>
       ↓
后端:
  1. 验证 token → 获取 user_id
  2. 查询订单主表 (校验归属: id = ? AND user_id = ?)
  3. 查询订单明细 (JOIN products 获取商品名称和分类)
  4. 返回 { ...order, items: [...] }
       ↓
前端: 替换列表为详情视图
  - 显示订单号、下单时间、状态
  - 表格展示每个商品: 名称、分类、单价、数量、小计
  - 底部显示合计金额
  - 提供"返回列表"按钮
```

## 三、关键技术点总结

| 技术点 | 说明 |
|-------|------|
| 参数化查询 `?` 占位符 | 防止 SQL 注入，所有用户输入都通过参数传递 |
| 动态 SQL 构建 | 根据查询条件动态拼接 WHERE 子句，避免写多个接口 |
| 分页查询 | `LIMIT` + `OFFSET` 实现，前端传递 page/limit 参数 |
| 防抖 (Debounce) | 搜索输入 300ms 延迟，避免每次按键都发请求 |
| Token 自动携带 | api.js 封装统一的请求方法，自动读取 token 并加到请求头 |
| 401 统一处理 | 收到 401 响应时自动清除 token 并跳转登录页 |
| 事务操作 | 下单时使用数据库事务，确保扣库存和创建订单的原子性 |
