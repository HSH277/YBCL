# 异步请求工具实现思路

## 一、需求分析

为电商前端封装一个独立的请求工具（request.js），实现：
1. 异步请求封装（XMLHttpRequest + Promise）
2. 对接后端 API 接口
3. 支持 Mock 数据模式（后端不可用时自动切换）
4. 商品列表的分页查询（每页发送一次请求）
5. 分类筛选功能

## 二、架构设计

## 三、request.js 核心设计

### 3.1 模块结构 (IIFE + 暴露全局对象)

```javascript
const Request = (function () {
  // 私有变量和方法
  var config = { baseURL: '...', timeout: 10000, useMock: false };
  var requestInterceptors = [];
  var responseInterceptors = [];

  function request(options) { ... }  // 核心请求方法
  function get(url, params) { ... }  // GET 便捷方法
  function post(url, data) { ... }   // POST 便捷方法

  // 公开 API
  return { config, request, get, post, put, del, addRequestInterceptor, addResponseInterceptor };
})();
```

### 3.2 基于 XMLHttpRequest 的 Promise 封装

```javascript
function request(options) {
  return new Promise(function (resolve, reject) {
    var xhr = new XMLHttpRequest();
    xhr.open(method, url, true);

    xhr.onreadystatechange = function () {
      if (xhr.readyState !== 4) return;
      var data = JSON.parse(xhr.responseText);
      resolve(data);  // 或 reject({ status, data })
    };

    xhr.send(data ? JSON.stringify(data) : null);
  });
}
```

**为什么用 XMLHttpRequest 而不是 fetch?**
- XMLHttpRequest 是最基础的异步请求 API，兼容性更好
- 更好地控制超时、错误处理
- 作为独立工具，不依赖较新的 API

### 3.3 拦截器机制

```javascript
// 请求拦截: 自动携带 Token
Request.addRequestInterceptor(function (options) {
  var token = localStorage.getItem('token');
  if (token) options.headers['Authorization'] = 'Bearer ' + token;
  return options;
});

// 响应拦截: 401 跳转登录
Request.addResponseInterceptor(function (data, status) {
  if (status === 401) {
    localStorage.removeItem('token');
    window.location.href = 'login.html';
  }
  return data;
});

// 响应拦截: 后端不可用时自动切换 Mock
Request.addResponseInterceptor(function (data, status) {
  if (status === 0) {
    Request.config.useMock = true;
  }
  return data;
});
```

### 3.4 自动切换 Mock 模式

```
页面加载 → 尝试请求后端 API
  → 成功 → 使用真实数据
  → 失败 (网络错误) → 自动切换 Mock 模式 → 使用模拟数据
```

## 四、分页查询实现

### 4.1 核心逻辑

```javascript
// 每次翻页发送一次新请求
function goPage(page) {
  currentPage = page;      // 更新当前页码
  loadProducts();          // 重新请求数据
  window.scrollTo(0, 0);   // 回到顶部
}

// 请求参数
var params = {
  page: currentPage,       // 当前页码
  pageSize: 6,             // 每页6条
  keyword: currentKeyword, // 搜索关键词
  category: currentCategory // 分类筛选
};
```

### 4.2 分页数据流

```
用户点击"第2页"
  → goPage(2)
  → currentPage = 2
  → loadProducts()
  → Request.get('/products', { page: 2, pageSize: 6 })
  → 后端返回: { list: [...6条], pagination: { page:2, totalPages:5, total:30 } }
  → 渲染商品卡片
  → 渲染分页控件 [上一页] [1] [2*] [3] [4] [5] [下一页]
```

### 4.3 搜索/筛选时重置页码

```javascript
// 搜索时
currentKeyword = '耳机';
currentPage = 1;  // 重置到第1页
loadProducts();

// 筛选时
currentCategory = '电子产品';
currentPage = 1;  // 重置到第1页
loadProducts();
```

## 五、Mock 数据实现

### 5.1 数据设计

- 30 条商品数据，覆盖 4 个分类（电子产品、服装、图书、生活用品）
- 支持关键词模糊匹配
- 支持分类精确筛选
- 模拟 200-500ms 随机网络延迟

### 5.2 Mock 分页算法

```javascript
// 筛选
var filtered = allProducts.filter(function (p) {
  return (!keyword || p.name.indexOf(keyword) !== -1)
      && (!category || p.category === category);
});

// 分页
var total = filtered.length;
var start = (page - 1) * pageSize;
var list = filtered.slice(start, start + pageSize);
```

## 六、前端适配策略

由于原有后端 API 返回格式为 `{ code, data: [...] }`（数组），而分页需要 `{ list, pagination }` 格式，products.js 中做了兼容适配：

```javascript
// 后端返回数组时，前端自行分页
if (Array.isArray(res.data)) {
  var start = (currentPage - 1) * PAGE_SIZE;
  var list = res.data.slice(start, start + PAGE_SIZE);
  // 包装成分页格式
}
```

这样无论是 Mock 数据还是真实后端，前端逻辑统一。
